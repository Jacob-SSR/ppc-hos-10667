# PT dashboard: หลาย visit และบริการเชิงรุก

## การนับ

- ใช้ `ovst.vn` เป็นหน่วยนับ visit และ HN ไม่ซ้ำเป็นจำนวนผู้ป่วย
- visit ที่มีค่าบริการโดยเจ้าหน้าที่กายภาพ (`doctor.position_id = 9`), มีบันทึกในทะเบียนกายภาพ OPD หรือพบคำระบุ `PT in/on community` จะปรากฏ แม้ยังไม่มี `vn_stat` งานชุมชนที่ยังไม่ลงค่าบริการจะแสดงรายได้ 0 และไม่เดาชื่อผู้ให้บริการ
- ตรวจตาราง `physic_main_opd` แล้ว `physic_main` ตามลำดับ โดยต้องมี `vn`, `vstdate`, `service_text` เหมือนกลไกค้นหาตารางเดิม
- ถ้าคนไข้มาทำกายภาพ VN แรก แล้วพบแพทย์ VN ที่สอง: นับเฉพาะ VN กายภาพ ส่วน VN พบแพทย์จะนับด้วยเฉพาะเมื่อมีงานกายภาพใน VN นั้นเอง
- ถ้าคนไข้มีงานกายภาพจริงทั้งสอง VN: นับ 2 visits และผู้ป่วย 1 ราย
- ไม่รวมค่าบริการจาก VN อื่นของ HN เดียวกัน รายได้ยังคงเป็นยอดรวมของ VN ที่เข้าเกณฑ์ตามพฤติกรรมเดิม
- เจ้าของงานใช้เจ้าหน้าที่กายภาพที่ลงค่าบริการยอดมากสุดก่อน แล้วใช้เจ้าหน้าที่กายภาพจากทะเบียน OPD ถ้ามีคอลัมน์ `doctor`, `doctor_code` หรือ `staff` ที่อ้างถึง `doctor.code` ได้ หากหาไม่ได้แสดง “ไม่ระบุ” โดยไม่เดาเป็น PT/PTA

## งานนอกพื้นที่

ค้นหา `pt in community` หรือ `pt on community` ในช่องข้อความของ visit นั้น เช่น CC, HPI, PMH, หมายเหตุ ข้อความวินิจฉัย บันทึกพยาบาล และรายละเอียดบริการกายภาพ ไม่จำกัด CC อีกต่อไป รองรับตัวเล็กใหญ่ ช่องว่างซ้ำ tab การขึ้นบรรทัดใหม่ และตัวคั่น `-`, `_`, `.` คำว่า `เชิงรุก opd` อย่างเดียวไม่เพียงพอ ต้องมีคำระบุ PT community ด้วย

ตรวจคอลัมน์ชนิดข้อความที่มีจริงผ่าน `information_schema` ในตาราง `ovst`, `opdscreen`, `ovst_doctor_diag`, `ovstdiag`, `ovst_seq`, `ovst_nurse`, `opd_ill_history`, `opd_note`, `opd_nurse_note`, `physic_main_opd`, `physic_main`, `physic_service`, `clinic_visit` โดยตารางลูกต้องมี VN เพื่อผูกกับ visit โดยตรง ค้นทะเบียนกายภาพทั้งสองตารางถ้ามีอยู่ ไม่เลือกแค่ตารางแรก

ค้นชื่อประเภทการมา/สถานะ (`ovstist`, `ovstost`), สาขา (`spclty`), แผนก (`kskdepartment`) และคลินิก (`clinic` ผ่าน `clinic_visit`) ที่เชื่อมกับ visit ด้วย โดยตรวจว่าคอลัมน์เชื่อมมีจริงก่อนสร้าง SQL ตาราง/คอลัมน์ที่ไม่มีจะถูกข้าม ข้อมูล schema cache 1 ชั่วโมง หากอ่าน schema ล้มเหลวจะแสดงข้อผิดพลาดแทนการซ่อนเป็นยอด 0

แถบด้านบนเลือก **ทั้งหมด / ในโรงพยาบาล / นอกพื้นที่ (เชิงรุก OPD)** และแสดงจำนวน visits ตามช่วงวันที่ โดยกรอง KPI ตาราง กราฟ คิวปัจจุบัน ข้อมูลสรุป AI และ Excel สอดคล้องกัน คิวแสดงเฉพาะวันนี้ตามพฤติกรรมเดิม ตัวเลขบนแถบเป็นจำนวน visit บริการ ไม่ใช่จำนวนคิว

การจัดกลุ่มนี้หมายถึงสถานที่ให้บริการ ไม่ได้อ้างอิงที่อยู่หรือสิทธิพื้นที่ของผู้ป่วย ไม่ค้นประวัติทุกครั้งด้วย HN และไม่คัดลอกข้อความระหว่าง VN คิววันนี้รับ visit ที่มีคำระบุ PT community แม้ main_dep ไม่ใช่แผนกกายภาพ แต่ยังต้องไม่จำหน่ายและไม่เป็นผู้ป่วยในตามเงื่อนไขคิวเดิม

## การค้นหาช่วงวันยาว

ค้นคำระบุงานชุมชนเป็นชุด VN ด้วย `UNION` ของแต่ละแหล่งข้อความ โดยทุกแหล่งกรองช่วงวันก่อน ไม่มี correlated subquery ค้นข้อความซ้ำต่อ visit และใช้ตัวกรองคำ `community` ก่อนประเมิน regex จากนั้นรวม VN งานชุมชนกับ VN ค่าบริการ/ทะเบียนกายภาพ แล้วดึงรายละเอียดเฉพาะชุดที่เข้าเกณฑ์ ครั้งละ 250 VN ค่าบริการทุกหมวดและเวลา PT รวมด้วย aggregation รอบเดียวต่อชุด

คิวใช้ชุด VN งานชุมชนของวันนี้ที่ค้นแล้ว จึงไม่ค้นข้อความซ้ำทั้งใน SELECT และ WHERE หากช่วงรายงานไม่ครอบคลุมวันนี้ จะค้นงานชุมชนเฉพาะวันนี้เพิ่มเติม

คำขอช่วงวันเดียวกันที่ยังทำงานอยู่ใช้ promise ร่วมกันใน process เดียว ไม่เริ่ม SQL ชุดใหม่เมื่อ auto refresh มาซ้อน เก็บผลสำเร็จไว้ 30 วินาที สูงสุด 8 ช่วงต่อ process และใช้ `withHeavySlot` จำกัดงานหนักตามค่าระบบเดิม ไม่เก็บข้อผิดพลาดเป็นผลสำเร็จ การค้นครั้งแรกยังขึ้นกับ MySQL ขนาดข้อมูลและดัชนีจริงของโรงพยาบาล

## ตรวจสอบก่อนใช้งานจริง

ทดสอบอัตโนมัติ: `node --test tests/*.test.mjs` (ใช้ Node ที่รองรับ TypeScript stripping และ `node:sqlite`), `npx tsc --noEmit` และ lint ไฟล์ที่แก้ไข

ยังต้องตรวจสอบกับ MySQL/HOSxP ของโรงพยาบาลจริง โดยเลือกวันที่มีเคสหลาย VN ที่ทราบแน่นอน เทียบ VN งานกายภาพกับรายการบน dashboard และตรวจคำกำกับใน CC ของแต่ละ VN รวมถึงผล Excel และยอดรวมในแถบพื้นที่แต่ละกลุ่ม

ไม่ต้องเปลี่ยนโครงสร้างฐานข้อมูล โค้ดนี้ไม่ได้ย้ายค่าบริการหรือแก้ข้อมูลผู้ป่วยใน HOSxP
