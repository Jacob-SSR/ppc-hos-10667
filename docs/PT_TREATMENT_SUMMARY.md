# สรุปค่ารักษาทางด้านกายภาพแบบเลือกหัตถการ

หน้า `/pages/pt-treatment-summary` อยู่ในเมนูหน่วยบริการ > สรุปค่ารักษากายภาพ ใช้สิทธิ์กลุ่ม PT ตามระบบเดิม รวม role ที่มีสิทธิ์ทั้งหมดและการมอบสิทธิ์ PT รายบุคคล

เลือกช่วงวันและหัตถการได้หลายรายการ ค่าเริ่มต้นเป็น 18 รหัสจาก SQL รายงาน HOSxP ที่ให้มา:

3050121, 3140481, 3140480, 3050157, 3050158, 3050170, 3050171, 3050172, 3002120, 3140479, 3002121, 3002123, 3002128, 3002127, 3002125, 3002126, 3002122, 3140407

ชื่อและตัวเลือกอ่านจาก nondrugitems จริง ค้นหาชื่อหรือรหัสเพื่อเพิ่ม/ลดได้ สูงสุด 200 รายการต่อคำขอ หากรหัสค่าเริ่มต้นไม่มีในทะเบียนจะแจ้งจำนวนที่พบ และไม่เดาชื่อหัตถการจากข้อความภาษาไทยที่เสีย encoding ใน log

ผลรายงานแยกตามรหัสหัตถการ หรือแยกหัตถการและสิทธิการรักษาเมื่อเลือก checkbox แสดงจำนวนผู้ป่วย HN ไม่ซ้ำ, จำนวนครั้ง VN ไม่ซ้ำ, จำนวนแถวรายการค่าบริการ, จำนวนหน่วย SUM(opitemrece.qty) และเงิน SUM(opitemrece.sum_price) เฉพาะรหัสที่เลือก กรองวันที่จาก ovst.vstdate จึงไม่ทิ้ง visit ที่ไม่มี vn_stat

ไม่ SUM(vn_stat.income) หลัง join รายการยา เพราะเป็นเงินทั้ง visit และจะซ้ำตามจำนวนบรรทัด ไม่เลือกสิทธิแบบสุ่มขณะ GROUP BY หัตถการอย่างเดียว ยอดรวมทั้งรายงานคำนวณคน/VN ไม่ซ้ำแยกต่างหาก เพราะคน/VN เดียวมีหลายหัตถการได้ ส่วนยอดเงิน จำนวนรายการและจำนวนหน่วยรวมตรงกับแถวรายละเอียด

ส่งออก Excel ทุกแถวของผลรายงานที่ยืนยันแล้ว พร้อมช่วงวันและแถวรวม และพิมพ์/PDF แนวนอนได้ หากแก้เงื่อนไขแล้วยังไม่กดแสดงรายงาน จะเตือนและคงช่วงวันของผลเดิมไว้ ไม่เปลี่ยนชื่อหัวรายงาน/Excel ให้ผิดกับข้อมูล

API `/api/pt-treatment-summary?mode=catalog` คืนทะเบียนรายการและชื่อโรงพยาบาล; report รับ start, end, icodes คั่นด้วย comma และ group=procedure|right ตรวจวันที่จริง ลำดับช่วงวัน รหัสรายการ จำนวนที่เลือก และรูปแบบการจัดกลุ่มก่อน query ทุกค่าจากผู้ใช้ bind ด้วย parameters ไม่คืนข้อมูลผู้ป่วยรายบุคคล

ทะเบียนรายการ cache 1 ชั่วโมง ผลรายงาน cache 60 วินาที สูงสุด 8 ชุดต่อ process คำขอซ้ำใช้ promise ร่วมกัน และผ่าน withHeavySlot ไม่เริ่มงานหนักซ้ำพร้อมกันสำหรับเงื่อนไขเดียวกัน

ตรวจด้วย `node --test tests/*.test.mjs`, `npx tsc --noEmit`, lint ไฟล์ที่แก้ไข และหน้าตัวอย่างที่ใช้ข้อมูลจำลอง ตรวจ Excel ที่ดาวน์โหลดจริงด้วย ก่อนใช้งานต้องเทียบยอดกับ MySQL/HOSxP โรงพยาบาลสำหรับวันที่และรหัสชุดเดียวกัน การนับเงินแก้การซ้ำจาก SQL เดิมจึงอาจได้ยอดต่างจากรายงานเดิมที่ SUM(v.income) หลัง join
