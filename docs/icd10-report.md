# Dashboard สถิติผู้ป่วยตามกลุ่มโรค (ICD-10)

หน้า `/pages/icd10-report` และ API `/api/icd10-report` อยู่ในสิทธิ์ REPORT ของระบบเดิม
มีเมนูในหมวดรายงาน ใช้รูปแบบหน้าจอเดิมตามที่ผู้ใช้เลือก

## เงื่อนไขและการนับ

- ค่าเริ่มต้นตาม SQL ตัวอย่าง: A00–A99, อายุ 1–100 ปี, 2025-10-01 ถึง 2026-09-02; กดค้นหาเพื่อโหลด
- เลือกโรคหลักอย่างเดียว หรือ PDx รวม DX0–DX5
- รับรหัสตัวเล็กและรหัสที่มีจุด โดยปรับเป็นตัวใหญ่และตัดจุดก่อนเปรียบเทียบ รวมรหัสย่อยของปลายช่วง เช่น A99.0
- วันที่และอายุรวมค่าขอบเขตทั้งสองด้าน
- ช่องข้อความวินิจฉัยค้นหาบางส่วนของ `ovst.diag_text` (ไม่เกิน 200 ตัวอักษร) ร่วมกับช่วงรหัส อายุ และวันที่ โดยไม่แยกตัวพิมพ์เล็ก/ใหญ่; เว้นว่างเพื่อใช้เงื่อนไขเดิม เครื่องหมาย `%` และ `_` เป็นข้อความธรรมดา ไม่ใช่ wildcard
- กรองข้อความก่อนนับสถิติและเลือกครั้งล่าสุดต่อ HN ทำให้กราฟ ตาราง และ CSV ใช้ข้อมูลชุดเดียวกัน
- จำนวนครั้งและกราฟรายเดือนนับ VN ไม่ซ้ำทุกครั้งที่เข้าเงื่อนไข
- จำนวนผู้ป่วยและตารางนับ HN ไม่ซ้ำ เลือกวันที่ล่าสุดที่เข้าเงื่อนไข หากวันเดียวกันเลือก VN สูงสุด ไม่ใช้ GROUP BY HN แบบสุ่มแถว
- อายุเฉลี่ยและกราฟช่วงอายุใช้ข้อมูลแถวล่าสุดของผู้ป่วยแต่ละคน
- Top 10 จัดอันดับ PDx ของทุกครั้งที่เข้าเงื่อนไข ดังนั้นในโหมดหลักและรอง PDx อาจอยู่นอกช่วงค้นหา
- ข้อความวินิจฉัยที่ผู้ใช้ระบุว่า `dingtext` ใช้คอลัมน์จริง `ovst.diag_text` ตามไฟล์ CSV และเชื่อม `ovst.vn = vn_stat.vn`
- ชื่อโรคใช้ `icd101.tname` ก่อน แล้วใช้ `name` หากไม่มีชื่อไทย
- CSV ส่งออกผู้ป่วยทุกแถว รวม diag_text; ตารางแบ่งหน้าละ 50 คน และปุ่มพิมพ์ใช้หน้าปัจจุบัน
- จำกัดการโหลด 100,000 ครั้ง; หากเกินจะตอบข้อผิดพลาดให้ลดช่วงค้นหา ไม่แสดงผลรวมที่ถูกตัดทอน

## การติดตั้งและตรวจสอบ

ใช้ `git am <path-to-patch>` ใน repository นี้ ไม่ต้องเพิ่ม dependency หรือแก้ schema
ใช้การเชื่อมต่อ `db` และ environment เดิม; API เป็น read-only และตอบ Cache-Control: no-store
ไม่ได้บรรจุ CSV หรือข้อมูลผู้ป่วยจริงไว้ในแพตช์ และไม่ได้เรียก SQL จัดการ report_access_log/reporttemplate ที่แนบมา

ตรวจด้วย:

```sh
node --test tests/icd10-report.test.mjs
npx tsc --noEmit
npx eslint app/pages/icd10-report/page.tsx app/api/icd10-report/route.ts lib/icd10-report.ts
```

ชุดทดสอบใช้ข้อมูลสมมติใน SQLite เพื่อทดสอบเงื่อนไข query; ต้องตรวจผลกับ MySQL/HOSxP จริงในระบบโรงพยาบาลก่อนใช้งานจริง โดยเฉพาะชื่อไทยและระยะเวลาค้นหาช่วงกว้าง
