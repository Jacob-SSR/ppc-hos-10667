# ติดตามทำฟันเจ้าหน้าที่จากทะเบียนบุคลากร HR

## ติดตั้งครั้งแรก

รายชื่อหลักมาจาก INFOMATION_PERSON ที่ผู้ใช้ให้ มีชื่อ เลขบัตร ตำแหน่ง หน่วยงาน และฝ่าย/แผนกครบ ไม่ใช้ doctor.active เป็นตัวกำหนดประชากรอีก จึงไม่ตัดบุคลากรที่ไม่มีรหัสผู้ให้บริการใน doctor ออก

1. ให้ IT รัน SQL นำเข้ารายชื่อที่ส่งให้เป็นไฟล์ส่วนตัว **บน DB_HOST2 ที่มีฐาน ppchos** ครั้งเดียวก่อนใช้งานรุ่นนี้ ไฟล์นั้นสร้าง `ppchos.staff_dental_roster` และนำเข้าทะเบียนทั้งหมดให้แล้ว ไม่ต้องรัน schema ซ้ำอีก
2. `docs/sql/staff_dental_roster.sql` ใน repository เป็น schema เปล่า ไม่มีรายชื่อจริง
3. Deploy ตามขั้นตอนเดิม แล้วเปิด หน่วยบริการ → ติดตามทำฟันเจ้าหน้าที่ ไม่ต้องเลือกไฟล์รายชื่อบนหน้าเว็บ

ไฟล์ SQL นำเข้ามีเฉพาะ CID คำนำหน้า ชื่อ นามสกุล ตำแหน่ง หน่วยงาน ฝ่าย/แผนก สถานะการทำงาน และลำดับ ไม่รวมเงินเดือน บัญชีธนาคาร วันเกิด หรือช่องทางติดต่อ **ห้าม commit ไฟล์นำเข้าที่มีรายชื่อจริงหรือ HR export ลง repository**

การนำเข้าซ้ำปิด active เฉพาะทะเบียนรายงานนี้แล้ว upsert snapshot ใหม่ใน transaction ไม่แก้ patient/doctor ของ HOSxP รายชื่อเก่าที่ไม่มีใน snapshot ล่าสุดคงอยู่เป็น inactive ใช้ CID เป็น primary key ป้องกันบุคคลซ้ำ

ถ้าตารางยังไม่ติดตั้งหรือไม่มีรายชื่อ API ตอบ 503 พร้อมข้อความให้ติดตั้งทะเบียน ไม่ fallback กลับไปใช้ doctor และไม่แสดงรายงานว่างเหมือนทุกคนมี 0 visit

## ใช้งาน

1. เลือกวันที่ ค่าเริ่มต้น 1 มกราคมปีปัจจุบันถึงวันนี้ตามเวลาไทย
2. เลือกแผนกรับบริการแล้วกด **ตรวจสอบผู้ที่ยังไม่ได้ทำฟัน**
3. กรอง **กลุ่มงาน/ฝ่าย, หน่วยงาน, ตำแหน่ง และสถานะ** ตามทะเบียน HR ตารางรายบุคคลอยู่ก่อนสรุป
4. **Excel ทั้งรายงาน** ส่งออกบุคลากรทั้งหมดในทะเบียน ตามวันที่และแผนกรับบริการของผล ไม่จำกัดตัวกรองสังกัด/ตำแหน่ง/สถานะบนหน้าจอ

Excel มี 5 ชีต: ยังไม่พบ visit, สรุปกลุ่มงานหน่วยงาน, บุคลากรทั้งหมด, ต้องตรวจสอบ และขอบเขตรายงาน สรุปหนึ่งแถวต่อกลุ่มงาน+หน่วยงาน+ตำแหน่ง ยอดรวมคนทุกแถวเท่ากับจำนวนคนในรายงาน

## แหล่งข้อมูล

- **รายชื่อ/ตำแหน่ง/สังกัด:** HR_STAFF_SQL อ่าน `ppchos.staff_dental_roster` ที่ active=1 ผ่าน db2 ข้อมูลตำแหน่ง หน่วยงาน และกลุ่มงาน/ฝ่ายตาม HR โดยตรง ไม่เดาจาก doctor_position หรือแผนกบริการ
- **แผนกรับบริการ:** GET `/api/staff-dental` อ่านทุก depcode จาก kskdepartment แสดงชื่อพร้อมรหัสเพื่อแยกชื่อซ้ำ SQL visit เชื่อม `kskdepartment.depcode = ovst.cur_dep` เหมือน incomplete-visit ตามที่ผู้ใช้ยืนยัน
- **ผู้ป่วย/visit:** ใช้การเชื่อมต่อ HOSxP เดิมผ่าน db

เลือกทุกแผนกเพื่อดูผู้ยังไม่พบ visit ทันตกรรมในโรงพยาบาล เมื่อเลือกแผนกเฉพาะ เครื่องหมายและจำนวน visit หมายถึงบริการเฉพาะแผนกนั้นในช่วงวันที่ที่เลือก บุคคลที่รับบริการแผนกอื่นอาจไม่มี visit ในแผนกที่เลือก ข้อมูลนี้แยกจากสังกัด HR อย่างชัดเจน หน้าเว็บ/Excel ระบุเงื่อนไขแผนก และต้องตรวจสอบใหม่เมื่อเปลี่ยนวันที่หรือแผนกก่อนส่งออก

## จับคู่ตัวบุคคลและติ๊กอัตโนมัติ

ใช้ CID จากทะเบียนจับคู่ patient.cid ก่อน ถ้ามี CID แต่ไม่พบผู้ป่วยจะไม่ไปจับคู่ชื่อคนอื่น รายการที่ไม่มี CID ที่ใช้ได้ใช้ชื่อ+นามสกุลครบทั้งสองช่องแบบ exact โดยตัดช่องว่าง ไม่ส่ง CID กลับเบราว์เซอร์หรือ Excel

เกณฑ์ทันตกรรมเหมือนรายงานเดิม: vn_stat มี opitemrece ใน VN เดียวกัน ผู้ลงค่าบริการเชื่อม doctor.position_id IN ('2','6') นับ COUNT(DISTINCT vn) ช่วงวันสิ้นสุดรวมเต็มวัน ไม่กรอง main_dep การเลือกรับบริการใช้ cur_dep

- มี visit → ติ๊กทำแล้ว
- จับคู่ตัวบุคคลได้แต่ไม่มี visit ในเงื่อนไข → ติ๊กยังไม่ทำ
- ไม่พบผู้ป่วย ชื่อตรงหลาย HN หรือ CID/HN ซ้ำหลายรายชื่อ → ต้องตรวจสอบ จำนวน visit ว่าง ไม่ติ๊กทั้งสองช่อง

ช่องติ๊กแก้ไขเองไม่ได้ ไม่ยืนยันว่ารักษาครบทุกหัตถการหรือครอบคลุมบริการนอกโรงพยาบาล สิทธิ์หน้า/API ใช้ DENTAL และผู้มีสิทธิ์รายงานทั้งหมดตามระบบเดิม API report ไม่บันทึกหรือเปลี่ยนทะเบียน

## ทดสอบ

`node --experimental-strip-types --test tests/staff-dental.test.mjs` ตรวจ HR roster ที่ไม่พึ่งรหัสผู้ให้บริการ, กลุ่มงาน/หน่วยงาน, CID/ชื่อซ้ำ, DISTINCT VN, วันที่, cur_dep ต่างจาก main_dep, catalogue แผนกชื่อซ้ำ, ยอดรวม และ Excel โดยใช้ SQLite หลังแปลง charset/date ของ MySQL

สภาพแวดล้อมพัฒนาไม่ได้เชื่อม HOSxP จริง ต้องนำเข้าทะเบียนและตรวจเทียบ HN ตัวอย่างกับรายงานทันตกรรมเดิมหลัง deploy ผล visit ในการทดสอบหน้าจอเป็นข้อมูลจำลอง
