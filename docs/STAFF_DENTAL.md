# ติดตามทำฟันเจ้าหน้าที่

เมนู **หน่วยบริการ → ติดตามทำฟันเจ้าหน้าที่** (`/pages/staff-dental`) เปิดให้ผู้มีสิทธิ์ DENTAL และผู้มีสิทธิ์ดูรายงานทั้งหมดตามระบบเดิม

1. เลือกช่วงวันที่ ค่าเริ่มต้นคือ 1 มกราคมปีปัจจุบันถึงวันนี้ตามเวลาไทย
2. เลือก Excel รายชื่อเจ้าหน้าที่ แล้วเลือกชีต เช่น `1 มีนาคม 2569` รองรับหัวตารางสองแถวของไฟล์ต้นฉบับ
3. กด **ตรวจสอบผู้ที่ยังไม่ได้ทำฟัน** ระบบดึงข้อมูลจาก HOSxP ผ่านการเชื่อมต่อ DB เดิม
4. หน้าแสดงผู้ที่ **ยังไม่พบ visit** ก่อน เลือกกลุ่มงาน/แผนกเพื่อดูรายชื่อ และกด Excel เพื่อส่งออกทั้งรายงาน

## รายชื่อและการจับคู่

ต้องมี ชื่อ, สกุล/นามสกุล และ กลุ่มงาน/แผนก รองรับคอลัมน์แผนกแยกจากกลุ่มงาน หากไม่มีแผนกจะใช้ชื่อกลุ่มงานเป็นแผนกด้วย จำกัด 500 คน/5 MB

ชื่อในไฟล์ใช้จับคู่ `patient.fname/lname` โดยตัดช่องว่าง ไม่ใช้คอลัมน์สถานะของไฟล์ต้นฉบับ ถ้ามี HN จะใช้ HN ก่อน และตรวจ CID ด้วยหากระบุ ถ้ามีเฉพาะ CID จะใช้ CID ชื่อที่ไม่พบหรือซ้ำหลาย HN เป็น **ต้องตรวจสอบ** และจำนวน visit เป็นค่าว่าง ไม่ถือว่าเป็น 0 visit หากพบปัญหาให้เติม HN/CID ที่ยืนยันแล้วในไฟล์และนำเข้าใหม่ รายชื่อซ้ำหรือหลายคนจับคู่กับ HN เดียวกันไม่รวมในยอดที่ยืนยันได้

ไฟล์อ่านในเบราว์เซอร์ ส่งเฉพาะรายชื่อที่จำเป็นไป POST `/api/staff-dental` ไม่บันทึกไฟล์/รายชื่อในฐานข้อมูลหรือ GitHub ไม่ใช้ localStorage และไม่ cache ผลรายงาน

## นิยาม visit

ใช้เกณฑ์เดียวกับ `lib/dental.service.ts`: `vn_stat` ที่มี `opitemrece` ใน VN เดียวกัน โดย `opitemrece.doctor` เชื่อม `doctor.position_id IN ('2','6')` นับ `COUNT(DISTINCT vn)` ไม่กรอง `main_dep` จำนวนรายการค่าบริการ/ผู้ให้บริการหลายคนใน VN เดียวกันไม่เพิ่มจำนวน visit

**ยังไม่พบ visit** คือจับคู่ตัวบุคคลได้ และไม่มี VN ตามเกณฑ์ในช่วงที่เลือก ไม่ยืนยันว่าบุคคลนั้นไม่เคยทำฟัน และไม่ครอบคลุมบริการนอกโรงพยาบาลหรือบริการที่ไม่ได้บันทึกตามเกณฑ์นี้ รายงานนี้วัด visit ตามระบบเดิม ไม่ใช่การยืนยันหัตถการเฉพาะอย่างหรือการรักษาครบ

รายงานสรุปแยกจำนวนทั้งหมด, รับบริการแล้ว, ยังไม่พบ visit และต้องตรวจสอบ โดยยอดคนทั้งสามกลุ่มรวมเท่ารายชื่อทั้งหมด Excel มีชีตผู้ยังไม่พบ visit, สรุปกลุ่มงาน/แผนก, เจ้าหน้าที่ทั้งหมด, ต้องตรวจสอบ และขอบเขตรายงาน ส่งออกตามช่วงวันที่ของผลที่แสดงและรายชื่อทั้งหมดที่นำเข้า ไม่จำกัดตามตัวกรองหน้าจอ เมื่อเปลี่ยนวันที่ต้องดึงรายงานใหม่ก่อนส่งออก

## ตรวจสอบก่อนใช้งานจริง

ใช้ DB/environment และขั้นตอน deploy เดิม ไม่ต้องสร้างตารางเพิ่ม ตรวจเทียบเจ้าหน้าที่ที่ทราบ HN กับรายงานทันตกรรมเดิม ทั้งเคสมี visit และไม่มี visit เนื่องจากสภาพแวดล้อมพัฒนาไม่มีการเชื่อมฐาน HOSxP จริง

ทดสอบอัตโนมัติ: `node --experimental-strip-types --test tests/staff-dental.test.mjs` ทดสอบนำเข้า, จับคู่ชื่อ/รหัส, ชื่อซ้ำ, สิทธิ์, จำนวน VN และวันเริ่ม/สิ้นสุด โดยรัน SELECT เดียวกับระบบผ่าน SQLite หลังแปลงเฉพาะไวยากรณ์ charset/date ของ MySQL การทดสอบนี้ไม่ได้แทนการตรวจ SQL กับฐาน HOSxP จริง
