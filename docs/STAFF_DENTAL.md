# ติดตามทำฟันเจ้าหน้าที่ — อ่านข้อมูลเท่านั้น

รายชื่อหลักมาจากไฟล์ทะเบียนบุคลากร HR ที่เก็บไว้บนเซิร์ฟเวอร์ ไม่สร้างตาราง ไม่ import รายชื่อ และไม่เขียนข้อมูลลงฐานใด รายงานใช้ SQL SELECT อ่าน kskdepartment, patient และ visit จาก HOSxP เท่านั้น

## วางไฟล์ครั้งแรก

1. ใช้ไฟล์ **staff-dental-roster.json** ที่เตรียมจาก HR export ให้เป็นการส่วนตัว ไม่ใช้ SQL นำเข้าเดิม
2. วางใน `private/staff-dental-roster.json` บนเครื่องที่รันแอป ให้บัญชีที่รันแอปอ่านไฟล์ได้
3. ถ้าใช้ Docker Compose โฟลเดอร์ `./private` บน host ถูก bind mount ไป `/app/private` แบบ `:ro` แล้ว ไม่ต้องนำไฟล์เข้า image
4. ถ้าใช้ path อื่น กำหนด `STAFF_DENTAL_ROSTER_FILE` เป็น absolute path ของไฟล์ภายในเครื่อง/container
5. เปิดรายงานแล้วกดตรวจสอบ ไม่ต้องเลือกหรือ upload รายชื่อบนหน้าเว็บ ไม่ต้องรัน SQL ใดเพื่อติดตั้งทะเบียน

โฟลเดอร์ private ถูก ignore ทั้ง Git และ Docker build context ข้อมูลจริงไม่อยู่ใน repository หรือ public ของ Next.js เปลี่ยนทะเบียนครั้งต่อไปด้วยการแทนไฟล์บน host แอปอ่านไฟล์ใหม่เมื่อกดตรวจสอบ ไม่เขียนกลับไฟล์

ไฟล์มีรูปแบบ version=1, people เป็น array ของ `staff_ordinal`, `cid`, `prefix`, `first_name`, `last_name`, `position_name`, `unit_name`, `department_name` เท่านั้น CID เก็บเป็นข้อความ ไม่รวมเงินเดือน บัญชีธนาคาร วันเกิด หรือช่องทางติดต่อ ตัวอ่านเลือกเฉพาะฟิลด์ที่จำเป็นและตรวจลำดับ/CID ซ้ำ ข้อมูลไม่ครบ หรือ JSON เสีย หากไม่มีไฟล์หรือข้อมูลใช้ไม่ได้ API ตอบ 503 พร้อมคำอธิบาย ไม่ fallback ไป doctor และไม่แสดงผลว่างเหมือนทุกคนมี 0 visit

## ใช้งาน

1. เลือกวันที่ ค่าเริ่มต้น 1 มกราคมปีปัจจุบันถึงวันนี้ตามเวลาไทย
2. เลือกแผนกรับบริการแล้วกด **ตรวจสอบผู้ที่ยังไม่ได้ทำฟัน**
3. กรอง **กลุ่มงาน/ฝ่าย, หน่วยงาน, ตำแหน่ง และสถานะ** ตามทะเบียน HR ตารางรายบุคคลอยู่ก่อนสรุป
4. **Excel ทั้งรายงาน** ส่งออกบุคลากรทั้งหมดตามวันที่/แผนกรับบริการของผล ไม่จำกัดสังกัด/ตำแหน่ง/สถานะที่กรองบนหน้าจอ

Excel มี 5 ชีต: ยังไม่พบ visit, สรุปกลุ่มงานหน่วยงาน, บุคลากรทั้งหมด, ต้องตรวจสอบ และขอบเขตรายงาน สรุปต่อกลุ่มงาน+หน่วยงาน+ตำแหน่ง ยอดรวมทุกแถวเท่ากับจำนวนคนทั้งหมด

## แหล่งข้อมูลที่แยกกัน

- รายชื่อ/ตำแหน่ง/หน่วยงาน/กลุ่มงาน อ่านจาก private HR file ไม่ใช้ doctor.active หรือ doctor_position กำหนดประชากร จึงไม่ตัดบุคลากรที่ไม่มีรหัสผู้ให้บริการออก
- แผนกรับบริการอ่านจาก kskdepartment ผ่าน GET `/api/staff-dental` ใช้ depcode เป็นค่าตัวเลือก SQL visit เชื่อม `kskdepartment.depcode = ovst.cur_dep` เหมือน incomplete-visit ตามที่ผู้ใช้ยืนยัน
- การจับคู่และ visit ใช้ SELECT กับ patient/vn_stat/opitemrece/doctor ผ่านการเชื่อมต่อ HOSxP เดิม ไม่ใช้ db2 สำหรับทะเบียนรายงาน

เลือกทุกแผนกเพื่อดูผู้ยังไม่พบ visit ทันตกรรมในโรงพยาบาล เลือกแผนกเฉพาะเพื่อดูสถานะบริการในแผนกนั้นในช่วงที่เลือก บุคคลที่รับบริการแผนกอื่นอาจไม่มี visit ในแผนกที่เลือก แผนกรับบริการแยกจากสังกัด HR ชัดเจน และเปลี่ยนวันที่/แผนกแล้วต้องตรวจสอบใหม่ก่อนส่งออก

## จับคู่และเครื่องหมายติ๊ก

CID จับคู่ patient.cid ก่อน หากมี CID แต่ไม่พบผู้ป่วยจะไม่จับคู่ชื่อคนอื่น ไม่ส่ง CID กลับเบราว์เซอร์หรือ Excel เกณฑ์ทันตกรรมเหมือนรายงานเดิม: vn_stat ที่มี opitemrece ใน VN เดียวกัน ผู้ลงค่าบริการเป็น doctor.position_id IN ('2','6') นับ COUNT(DISTINCT vn) รวมวันสิ้นสุดเต็มวัน ไม่กรอง main_dep

- มี visit → ติ๊กทำแล้ว
- จับคู่ตัวบุคคลได้แต่ไม่มี visit ในเงื่อนไข → ติ๊กยังไม่ทำ
- ไม่พบผู้ป่วย ชื่อตรงหลาย HN หรือ HN ซ้ำหลายรายชื่อ → ต้องตรวจสอบ จำนวน visit ว่าง ไม่ติ๊กทั้งสองช่อง

ช่องติ๊กแก้ไขเองไม่ได้ ไม่ครอบคลุมบริการนอกโรงพยาบาลหรือยืนยันรักษาครบทุกหัตถการ สิทธิ์หน้า/API ใช้ DENTAL และสิทธิ์รายงานทั้งหมดตามระบบเดิม POST เป็นการร้องขอผลรายงาน ไม่ใช่การเขียนข้อมูล
