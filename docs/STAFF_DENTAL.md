# ติดตามทำฟันเจ้าหน้าที่ แยกตามตำแหน่ง

เมนู **หน่วยบริการ → ติดตามทำฟันเจ้าหน้าที่** (`/pages/staff-dental`) ดึงรายชื่อจาก `doctor.active = 'Y'` ผ่าน SQL ไม่ต้องเลือกไฟล์

1. เลือกวันที่ ค่าเริ่มต้น 1 มกราคมปีปัจจุบันถึงวันนี้ตามเวลาไทย
2. กด **ตรวจสอบผู้ที่ยังไม่ได้ทำฟัน**
3. เลือก **แผนกรับบริการ** แล้วกดตรวจสอบใหม่ ใช้ **ตำแหน่ง** และ **สถานะ** กรองรายชื่อในผล ตารางรายบุคคลอยู่ก่อนสรุป
4. กด **Excel ทั้งรายงาน** เพื่อดาวน์โหลด 5 ชีต: ยังไม่พบ visit, สรุปตามตำแหน่ง, รายการ active ทั้งหมด, ต้องตรวจสอบ และขอบเขตรายงาน

## ตำแหน่งเจ้าหน้าที่

ใช้ `doctor_position.id = doctor.position_id` และ `doctor_position.name` เป็นตำแหน่ง รวมยอดเป็นหนึ่งแถวต่อตำแหน่ง หากไม่มีตำแหน่งแสดง **ไม่ระบุตำแหน่ง** ไม่อ่าน `doctor.department`

## แผนกรับบริการ

ตามที่ผู้ใช้ยืนยัน แผนกคือ **แผนกรับบริการของ visit** ไม่ใช่สังกัดเจ้าหน้าที่ รายชื่อแผนกทั้งหมดอ่านจาก `kskdepartment` ผ่าน GET `/api/staff-dental` ใช้ `depcode` เป็นรหัสตัวเลือก และแสดงชื่อพร้อมรหัสเพื่อแยกชื่อแผนกที่ซ้ำกัน

SQL เชื่อม `LEFT JOIN ovst ov ON ov.vn = v.vn` และ `LEFT JOIN kskdepartment k ON k.depcode = ov.cur_dep` เหมือนหน้า incomplete-visit เมื่อเลือกแผนกเพิ่ม `k.depcode = ?` แบบ parameterized ไม่ใช้ main_dep หรือ doctor.department ทุกแผนกยังนับ VN ที่ไม่มี ovst/ข้อมูลแผนกได้ โดยไม่ทำให้ visit ตกหล่นจาก INNER JOIN

เลือกทุกแผนกเพื่อดูว่าใครยังไม่พบ visit ทันตกรรมในโรงพยาบาล เมื่อเลือกแผนกเฉพาะ เครื่องหมายทำแล้ว/ยังไม่ทำและจำนวน visit หมายถึงบริการเฉพาะแผนกนั้นตาม cur_dep ในช่วงวันที่ที่เลือก บุคคลที่ทำฟันในแผนกอื่นอาจยังไม่พบ visit ในแผนกที่เลือก รายชื่อหลักยังเป็น doctor.active ทั้งหมด ไม่ได้จัดเจ้าหน้าที่เข้าสังกัดตามแผนกนั้น

หน้าเว็บและ Excel ระบุชื่อแผนก/ช่วงวันที่ของผลอย่างชัดเจน และแสดงชื่อแผนกที่พบ visit ของแต่ละราย เมื่อเปลี่ยนแผนกต้องตรวจสอบใหม่ก่อนส่งออก ไม่ให้ส่งออกผลเก่าโดยใช้ชื่อแผนกใหม่

รายชื่อหลักคือรายการรหัสเจ้าหน้าที่ active ใน doctor จำนวนแสดงเป็นรายการเพราะบุคคลหนึ่งอาจมีหลาย doctor.code ไม่ใช่บัญชีบุคลากรเดิม 177 คน และไม่รับรายชื่อจากผู้เรียกมาแทนฐานข้อมูล

## visit และเครื่องหมายติ๊ก

ใช้ CID ของ doctor จับคู่ `patient.cid` ก่อน หากไม่มี CID ที่เป็นตัวเลข 13 หลัก หรือเป็นเลขซ้ำทั้ง 13 ตำแหน่ง จะใช้ชื่อและนามสกุลที่ครบทั้งสองช่องแทน โดยตัดช่องว่างและเปรียบเทียบ exact ถ้ามี CID แล้วแต่ไม่พบผู้ป่วยจะไม่เปลี่ยนไปจับคู่ชื่อคนอื่น ไม่ส่ง CID กลับเบราว์เซอร์หรือ Excel

เกณฑ์บริการตรงกับรายงานทันตกรรมเดิม: `vn_stat` ที่มี `opitemrece` ใน VN เดียวกัน โดยผู้ลงค่าบริการเชื่อม `doctor.position_id IN ('2','6')` นับ `COUNT(DISTINCT vn)` ไม่กรอง main_dep

- มี visit ในช่วงที่เลือก → ติ๊ก **ทำแล้ว**
- จับคู่ตัวบุคคลได้และไม่มี visit → ติ๊ก **ยังไม่ทำ**
- CID ซ้ำหลาย doctor.code, ชื่อตรงหลาย HN, ไม่พบผู้ป่วย หรือหลายรายชื่อจับคู่ HN เดียวกัน → **ต้องตรวจสอบ** จำนวน visit เป็นค่าว่างและไม่ติ๊กทั้งสองช่อง

เครื่องหมายแก้ไขเองไม่ได้ Excel ใช้ ✓ ตามสถานะเดียวกัน การไม่มี visit ไม่ครอบคลุมบริการนอกโรงพยาบาลหรือบริการที่บันทึกไม่ตรงเกณฑ์ และไม่ยืนยันว่ารักษาครบทุกหัตถการ

POST `/api/staff-dental` รับ start/end และ departmentCode ไม่เพิ่มตารางหรือบันทึกรายชื่อ และไม่ cache ผล ตรวจรหัสแผนกกับทะเบียนจริงก่อนดึงรายงาน สิทธิ์หน้า/API ใช้ DENTAL กับสิทธิ์รายงานทั้งหมดตามระบบเดิม Excel ส่งออกทุก active record ตามวันที่/แผนกของผล ไม่จำกัดตำแหน่งหรือสถานะที่กรองบนหน้าจอ

## การทดสอบ

`node --experimental-strip-types --test tests/staff-dental.test.mjs` ตรวจ SQL active roster, ตำแหน่ง, CID ซ้ำ, การจับคู่, DISTINCT VN, วันเริ่ม/สิ้นสุด, catalogue ทุก depcode, cur_dep ต่างจาก main_dep, visit ที่ไม่มีข้อมูลแผนก, สรุปต่อตำแหน่ง, เงื่อนไข/เครื่องหมายใน Excel และสิทธิ์ โดยใช้ SQLite หลังแปลงไวยากรณ์ charset/date ของ MySQL

CSV ของผู้ใช้ใช้ยืนยันโครงสร้างเท่านั้น ไม่ใส่ชื่อหรือ CID จริงใน repository สภาพแวดล้อมพัฒนาไม่ได้เชื่อม HOSxP จริง จึงต้องตรวจเทียบ HN ตัวอย่างกับรายงานทันตกรรมเดิมหลัง deploy
