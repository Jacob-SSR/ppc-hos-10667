# ติดตามทำฟันเจ้าหน้าที่

เมนู **หน่วยบริการ → ติดตามทำฟันเจ้าหน้าที่** (`/pages/staff-dental`) ใช้รายชื่อจาก `doctor.active = 'Y'` โดยตรง ไม่ต้องเลือกไฟล์รายชื่อ สิทธิ์หน้า/API อยู่ใน DENTAL และผู้มีสิทธิ์รายงานทั้งหมดตามระบบเดิม

1. เลือกช่วงวันที่ ค่าเริ่มต้นคือ 1 มกราคมปีปัจจุบันถึงวันนี้ตามเวลาไทย
2. กด **ตรวจสอบผู้ที่ยังไม่ได้ทำฟัน** ระบบอ่านรายชื่อและ visit จาก HOSxP ผ่าน SQL โดยใช้ DB เดิม
3. หน้าแสดงผู้ที่ **ยังไม่พบ visit** ก่อน กรองตำแหน่ง/แผนก หรือเลือกดูผู้รับบริการแล้ว/ต้องตรวจสอบได้
4. กด **Excel ทั้งรายงาน** เพื่อดาวน์โหลดผลรายงาน 5 ชีต

คอลัมน์ **ทำแล้ว / ยังไม่ทำ** ติ๊กอัตโนมัติตาม visit ของช่วงวันที่ที่เลือก แก้ไขเองไม่ได้: พบ visit ติ๊กทำแล้ว; จับคู่ตัวบุคคลได้แต่ไม่มี visit ติ๊กยังไม่ทำ; รายการต้องตรวจสอบไม่ติ๊กทั้งสองช่อง ใน Excel ใช้เครื่องหมาย ✓ ตามสถานะเดียวกับหน้าเว็บ

หน้าเริ่มจากกลุ่มยังไม่ทำ เลือก **สถานะ → ทำแล้ว (มี visit)** หรือกดการ์ดชื่อเดียวกันเพื่อดูรายการที่ติ๊กทำแล้ว ตารางรายบุคคลอยู่ก่อนตารางสรุป ตัวย่อยแผนกใช้ชื่อ **แผนกตามทะเบียนเจ้าหน้าที่** เพื่อแยกจากแผนกที่รับบริการในรายงาน incomplete-visit

## รายชื่อและการจับคู่

`ACTIVE_DOCTOR_SQL` ใน `lib/staff-dental.ts` อ่าน `doctor` และ LEFT JOIN `doctor_position.id = doctor.position_id` ใช้ชื่อตำแหน่งจาก `doctor_position.name` และชื่อแผนกจาก `doctor.department` ข้อมูล `[][ห้องฉุกเฉิน]` แสดงเป็น `ห้องฉุกเฉิน` ส่วน NULL, ค่าว่าง และ `[]` แสดง `ไม่ระบุ` หลายชื่อแผนกในระเบียนเดียวแสดงร่วมกัน ไม่กระจายเป็นหลายแถว

ไม่ JOIN `doctor_department_id` กับ `kskdepartment.depcode` เพราะตัวอย่างข้อมูลไม่มีรหัสที่ตรงกัน และ `doctor.department` เป็นข้อความ ไม่ใช่ depcode ข้อมูลนี้ไม่ได้ยืนยันกลุ่มงานตามบัญชีบุคลากรเดิม จึงใช้หัวข้อ **ตำแหน่ง/แผนก** แทนการเดากลุ่มงาน

SQL หน้าอื่นที่ตรวจเทียบ: `lib/hospital-profile.service.ts` ใช้ `kskdepartment.depcode = ovst.main_dep`; `lib/deptStatus.service.ts` ใช้ `ovst.cur_dep/last_dep` ซึ่งเป็นแผนกของ visit ผู้ป่วย ส่วน `lib/rdu.queries.ts` ใช้ `doctor_position.id = doctor.position_id` เหมือนรายงานนี้ จึงไม่เปลี่ยนแผนกที่รับบริการมาเป็นแผนกที่เจ้าหน้าที่ทำงานโดยไม่มีข้อมูลเชื่อมโยง

ตามที่ผู้ใช้เลือก ประชากรรายงานคือ **รายการรหัสเจ้าหน้าที่ active ใน doctor** ไม่ใช่รายชื่อ 177 คนใน Excel เดิม ไม่รับรายชื่อที่ผู้เรียกส่งมาแทนฐานข้อมูล จำนวนแสดงเป็นรายการ เนื่องจากบุคคลหนึ่งอาจมีหลาย doctor.code รหัสเจ้าหน้าที่คงเลขศูนย์นำหน้าไว้

ใช้ CID จับคู่ `patient.cid` ก่อน ถ้าไม่มี CID ที่เป็นเลข 13 หลัก หรือเป็นเลขซ้ำทั้ง 13 ตำแหน่ง จะใช้ชื่อ/นามสกุลที่ครบทั้งสองช่องแทน โดยตัดช่องว่างและเปรียบเทียบแบบ exact หากมี CID แล้วแต่ไม่พบผู้ป่วย จะไม่เปลี่ยนไปจับคู่ชื่อคนอื่น

CID ซ้ำในหลาย doctor.code, ชื่อตรงหลาย HN, ไม่พบผู้ป่วย หรือหลายระเบียนจับคู่ HN เดียวกัน จะเป็น **ต้องตรวจสอบ** จำนวน visit เป็นค่าว่าง ไม่ถือว่าเป็น 0 และไม่รวมยอด visit จนกว่าจะแก้ทะเบียนแล้วดึงใหม่ แสดง doctor.code เพื่อให้ตรวจแก้ได้ ไม่ส่ง CID กลับเบราว์เซอร์หรือ Excel

POST `/api/staff-dental` รับเพียง `start` และ `end` ไม่มี upload, บันทึกรายชื่อเพิ่ม หรือ cache ผลรายงาน ไม่ต้องสร้างตารางเพิ่ม

## นิยาม visit

ใช้เกณฑ์เดียวกับ `lib/dental.service.ts`: `vn_stat` ที่มี `opitemrece` ใน VN เดียวกัน โดย `opitemrece.doctor` เชื่อม `doctor.position_id IN ('2','6')` นับ `COUNT(DISTINCT vn)` ไม่กรอง `main_dep` จำนวนรายการค่าบริการ/ผู้ให้บริการหลายคนใน VN เดียวกันไม่เพิ่มจำนวน visit

**ยังไม่พบ visit** คือจับคู่ตัวบุคคลได้ และไม่มี VN ตามเกณฑ์ในช่วงที่เลือก ไม่ยืนยันว่าบุคคลนั้นไม่เคยทำฟัน และไม่ครอบคลุมบริการนอกโรงพยาบาลหรือบริการที่ไม่ได้บันทึกตามเกณฑ์นี้ รายงานนี้วัด visit ตามระบบเดิม ไม่ใช่การยืนยันหัตถการเฉพาะอย่างหรือการรักษาครบ

รายงานสรุปแยกจำนวนรายการทั้งหมด, รับบริการแล้ว, ยังไม่พบ visit และต้องตรวจสอบ โดยสามกลุ่มรวมเท่าจำนวน active records Excel มีชีตผู้ยังไม่พบ visit, สรุปตำแหน่งแผนก, รายการ active ทั้งหมด, ต้องตรวจสอบ และขอบเขตรายงาน ส่งออกทุก active record ตามช่วงวันที่ของผล ไม่จำกัดตามตัวกรองหน้าจอ เมื่อเปลี่ยนวันที่ต้องตรวจสอบใหม่ก่อนส่งออก

## ตรวจสอบก่อนใช้งานจริง

ใช้ DB/environment และขั้นตอน deploy เดิม ไม่ต้องสร้างตารางเพิ่ม ตรวจเทียบเจ้าหน้าที่ที่ทราบ HN กับรายงานทันตกรรมเดิม ทั้งเคสมี visit และไม่มี visit เนื่องจากสภาพแวดล้อมพัฒนาไม่มีการเชื่อมฐาน HOSxP จริง

ทดสอบอัตโนมัติ: `node --experimental-strip-types --test tests/staff-dental.test.mjs` ทดสอบ SQL รายชื่อ active, แผนกว่าง, CID ซ้ำ, จับคู่ตัวบุคคล, สิทธิ์, จำนวน VN และวันเริ่ม/สิ้นสุด โดยรัน SELECT ผ่าน SQLite หลังแปลงไวยากรณ์ charset/date ของ MySQL ข้อมูล CSV ของผู้ใช้ใช้ยืนยันโครงสร้างเท่านั้น ไม่ใส่ชื่อหรือ CID จริงลง repository การทดสอบนี้ไม่ได้แทนการตรวจ SQL กับฐาน HOSxP จริง
